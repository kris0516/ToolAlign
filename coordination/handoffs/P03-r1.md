## 构造、序列化和回收条件（供 P04 核对）

1. 调用方在父进程构造 `ModelBackend`。spawn 导入其类并通过正常 Python 序列化重建实例状态；类需可导入，状态需可 pickle。`generate()` 实际在同一个自有模型子进程执行，最多三次决策保留该子进程中的 backend 状态。后续 ModelInput/GenerationConfig 通过有界 JSON 传入，不传 OracleTask 或标签。
2. 已加载 MLX 权重对象、张量、C 扩展句柄、锁、lambda/局部闭包的跨进程兼容性 **NOT_RUN**。冻结 `ModelBackend` Protocol 没有承诺这些对象可 pickle。可供 P04 调研的方向是父进程只持配置、子进程首次 generate 才加载的 adapter；本包未实现或声称其可用，不改变公共接口。
3. `LocalToolRegistry` 在父进程构造，含 `threading.Lock` 与一次性签发记录，不会 pickle 到工具进程。工具子进程只接收固定名称集合、registry hash、已快照的原生调用与 host-only 故障枚举，然后在子进程重新构造 registry、核验相同 hash，执行源码绑定函数。executor 与 oracle 留在父进程。
4. 父进程保存亲自 start 的 `multiprocessing.Process` 对象；结束时 join，仍运行才 terminate，必要时 kill，再 join。确认 `is_alive()==False` 与实际 exitcode 后才标 `reaped`、close handle 并删除自己的临时目录。没有 PID 扫描、进程组清理或丢弃 future 的替代实现。
5. 测试确认模型/工具均已进入阻塞操作后才触发取消，并核对退出码、reaped、active_children 中无该 PID；另一个独立进程保持存活。所有回收只针对持有的自有进程；进程隔离不冒充不受信代码的 OS 权限沙箱。

## 关键逻辑与边界

ValidatedCall 不是权限凭证：registry 保存对象身份与调用原始 hash；executor 消费该记录，对副本重新做 schema/hash/version/policy 检查。构造/复制伪造对象、修改已验证 mapping、跨 registry、旧版本和重放均拒绝。历史 `ta_` 工具、sandbox_only 或数据 schema 不会创建执行绑定。

Oracle 对完整允许策略和结构化结果评分，包括对象/日期/版本/数值以及每步 status/error_code/retryable；多种合法策略明确列出。错误对象即使 schema 合法、工具正常返回且最终答案自称正确，仍判失败。未知真值如实返回 unknown，无模型自评。

UTC deadline 固定持久化，单调时钟约束整个请求；工具的取消信号也包含总单调截止，墙钟倒跳不能延長请求。tokens、决策、轮次与 latency 累计；没有新增全局 token 总量配置。未返回响应时 token_accounting_complete=false；超界 raw 保留 hash/大小/截断标志及可用计数。
