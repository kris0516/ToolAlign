## 问题和修复

原 Python 相等比较把 `false` 与 `0`、`true` 与 `1` 混同。R1 的有效原创夹具证明观察引用、schema enum 差异和 target 校验三个入口存在问题；E1 在实际合并后的原代码上复现同一组 **3 failed / 7 passed**。同轮材料反例还证明：静态 HTML 中完整 Example 的 `additionalProperties` 从 `false` 换成 `0` 后，原校验器仍认为内容一致。

三个原文件统一使用新增 `json_values.py` 的比较规则：以已解析的有限 JSON 值生成稳定键，保留 null、布尔、字符串、数字、数组、对象及嵌套值的区别。对象键顺序和 JSON 空白不影响结果，数组顺序保留；整数与浮点表示及浮点零符号也保留。不接受非有限数字、非 JSON 容器或非字符串对象键。

- `semantic_view.py` 的结构差异、工具集和消息复用、观察引用均保留 JSON 类型；新元数据同时绑定 renderer 和比较辅助模块。
- `verify_semantic_views.py` 对原工具、完整前缀、目标、覆盖元数据和显示身份使用相同比较规则；工具集及消息引用必须是范围内的整数，布尔和浮点值不能作为索引。
- `check_materials.py` 对两 engine 记录、显示 JSON 块、完整数组、mask、计数和预算布尔值作类型保真核对；token ID 必须是非负整数。

生产源码、抽样器、汇总器、数据、配置、依赖、构建和协调状态未另改。
