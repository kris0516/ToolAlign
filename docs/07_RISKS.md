# 07｜风险登记与降级策略

优先级 P0=阻止发布或污染结论；P1=显著影响范围/效率；P2=后续优化。状态初始均为 OPEN，不能把写了对策当成已解决。

| ID | 级别 | 风险/触发 | 对策与责任 |
|---|---|---|---|
| R01 | P0 | SFT→DPO adapter/template 不兼容 | T1 在 P01 做前向/保存加载对照；失败则一次备选或降级 |
| R02 | P0 | reference 意外是原始模型而非 SFT | 冻结 hash、相等起点 ln2 与 no-grad 检验；R1 审查 |
| R03 | P0 | train/test 同工具模板泄漏 | D1 先 group split，E1 检查交集；污染需新测试版本 |
| R04 | P0 | oracle 只检查运行不报错 | E1 提供语义错误但执行成功的反例与多解测试 |
| R05 | P0 | 公开私有数据、凭据或许可错误 | S0 发布 allowlist、来源审查，不自动上传全量数据/模型 |
| R06 | P0 | 模型输出触发任意代码/命令 | 白名单固定工具，不 eval/exec；不直接执行 BFCL 文本 |
| R07 | P0 | 公共 PR 在个人 Mac 携密钥运行 | 公共 CI 仅受限 CPU；本机验证显式选择可信 commit |
| R08 | P1 | 48GB 被并行 Codex/IDE/模型挤满 | 共享 GPU 锁、监控系统压力、停止其他模型进程 |
| R09 | P1 | 数据 schema 太长，1024 无法容纳 | 统计长度、bucket、排除报告，不静默截断 |
| R10 | P1 | 偏好生成/评测比训练更耗时 | P01 分项估时；减规模而不减必要对照 |
| R11 | P1 | DPO 无提升或退化 | 允许负结果；分析错误分布/label noise，不反复调测试集 |
| R12 | P1 | 多对话同时改公共契约 | S0 单点所有权，契约先合并再分发 |
| R13 | P1 | “resume”只恢复 adapter | 明示 weights_only_restart，不能声称精确续训 |
| R14 | P1 | 不同量化位宽和模型容量混杂 | 一次对照只改一项，全部身份 hash 入表 |
| R15 | P1 | cache 混用户、混 adapter 或吞工具 schema | exact prefix + model/tenant key，失效测试，旋转 cache 后移 |
| R16 | P1 | Supervisor 没有原生线程创建能力 | 使用独立对话提示词由 kris 转交，不改用 sub-agent |
| R17 | P1 | GitHub 当前连接无写权限/无创建操作 | 使用本机经授权 gh 创建新仓库；不声称已经远端发布 |
| R18 | P2 | 投机解码反而更慢 | 可选实验；保留负结果、不进入默认部署 |
| R19 | P1 | 学生只会运行 Codex 生成代码 | 每阶段 kris 做解释/手改/坏例分析，见学习检查 |
| R20 | P1 | 浮动依赖/模型上游改变 | pin commit/版本，升级走回归；老结果保留环境身份 |

## 紧急停止条件

发现凭据/隐私公开、非法执行能力、评测污染、错误 reference、系统持续内存压力或未知费用时，先停止对应工作并保存可审查状态。Supervisor 记录影响范围、是否影响已生成结果、修复与重跑计划。不要为了按时完成改口径或隐藏失败。
