# 02｜数据治理、许可与隔离

## 1. 数据源选择

默认优先 `Team-ACE/ToolACE`，发布方标记 Apache-2.0；`Salesforce/xlam-function-calling-60k` 标记 CC-BY-4.0 且有访问条件确认，因此是**可选补充**，不让首期交付依赖用户尚未获得的访问。来源卡及核实日期见 [S04/S05](09_SOURCES.md)。不要未经确认自动接受条款。

数据仓库中仅提交下载/转换方法、来源 manifest 和允许公开的小型例子，不提交全量镜像。发布方的许可标签并不等于所有衍生材料都可以无条件重新授权；须保存原始声明、署名、转换记录与疑点。

原始模型选择 `Qwen/Qwen3-0.6B` / `Qwen/Qwen3-1.7B`，记录准确 revision、许可证文件、tokenizer 与 template。禁止从随机个人上传的量化权重绕过来源检查。

## 2. 三种数据不混用

**训练数据：** 公开 tool-call 样本，可能只有工具描述和预期调用，不一定有可运行的真实 API。它们可用于监督训练，但不能据此声称跑通真实系统。

**自建可执行任务：** 在确定的本地开发运维工具环境中生成/人工检查，具有隐藏 oracle，例如读取测试报告、过滤日志、查询版本兼容表、汇总结构化记录、比较候选配置。工具实现与数据来源应是原创或许可明确。

**外部 benchmark：** BFCL 固定 revision、固定分类子集。不给训练器，也不用于偏好挖掘。它是外部评测，但不能声称知道底座预训练阶段完全没有污染。

## 3. 数据处理顺序

1. 下载时写来源、访问时间、revision、原始文件 hash、license 与可公开范围。
2. 规范化角色、工具 schema、参数类型、多个调用顺序；异常条目隔离，不自行“补真值”。
3. 对 tool schema、业务任务模板、来源记录和语义近重复建立 group。
4. **先分组切分，再做问法改写、增强和负例构造。** 同源改写必须留在同一 split。
5. 再 tokenize；统计 prompt/schema/completion 占比及 P50/P90/P95/P99 token 长度。
6. 长样本采用明确 bucket 或排除；禁止截去关键 tool 参数/最终回答后仍当完整样本训练。
7. 用训练集样本开展 smoke，验证集定超参，最终集仅用于冻结后的评测。

推荐 split 目标为训练 80%、验证 10%、最终测试 10%，但**group 隔离优先于精确比例**。另保留工具/schema 未见过的 OOD 组；分开报告同域与 OOD。

## 4. 可复核 manifest

每个条目须可追溯：`source_record_hash → normalized_hash → group_id → split → augmentation_parent → training_run`。

数据集级报告包含：原始条数、各过滤理由计数、最终条数、工具数、类别分布、语言分布、长度分布、完全重复/近重复、split 交集检查、许可拒收项目、人工抽查样本号与错误率。

所有 pipeline 参数、随机种子和代码 revision 入 manifest。同一命令在同一输入版本下应生成相同分组与划分；时间字段不得影响样本 ID。

## 5. 偏好数据的构造

优先用冻结的 SFT 模型对 **train-only** 任务生成多个候选；只保留 oracle 能判断、chosen 真正完成目标且 rejected 有明确失败原因的对。能否正确执行与实际任务达成分别检查。

处理多解：两个不同工具序列都能达成目标，且成本策略未预定义时，标为 tie，不硬造优劣。chosen 的可靠性不能仅由同一模型判断。拒绝把外观更漂亮、JSON key 顺序不同、回答更短直接当优劣。

保留几类硬负例：工具混淆、参数语义错误、无工具需求却调用、前提信息缺失、错误恢复选择不当。简单 JSON 破坏只作为 sanity/消融；不要让它主导 DPO 数据。

人工抽查最少 100 个有效对或总数的 10%（取较大值，但不超过全量），分层覆盖主要错误类型。若误标率超过事先设定的可接受阈值，暂停正式训练、修 oracle/数据规则并重新采样；P00 预注册误标率上限为 5%（严格大于 5% 时阻断，unknown 计入误标）；配置见 `configs/protocol.v1.json`，不能看结果后改变。

## 6. 公开发布规则

允许：原创工具与 schema、明确允许发布的合成 fixtures、下载/预处理脚本、切分 hash、去敏统计、许可证清单、获得发布许可的 adapter。

禁止默认公开：用户聊天、健康/饮食资料、LiDAR capture、GitHub 私有仓库快照、云 API key、服务账号、原始大数据镜像、隐藏 oracle 的正式测试答案（测试期）。最终开源 oracle 前必须冻结并命名数据版本；今后对该版本调参不再叫盲测。

不得以删除人名代替完整去敏；路径、项目编号、日志中的 token、设备标识也要检查。

## 7. 数据门 G-DATA

通过条件：所有来源有许可/访问记录；split 无可识别同组交叉；至少一次人工质量审查；训练配置绑定 manifest；最终集未用于选择模型。任何一项不满足，正式 benchmark 结论都不得进入 README。
