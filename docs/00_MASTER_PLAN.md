# 00｜总体计划与范围控制

规划基线：plan-v0.1。日期：2026-09-06。状态：P00 已独立审查、合并并验证，后续按 BOARD 分发。D1–D10 表示从实际开工日起的工作日序号，**不是固定日历日期**。

## 1. 为什么做这个项目

项目主线不是再搭一个聊天页面，而是回答：**小模型在工具选择和执行反馈上，哪些能力可以通过数据与后训练改善，哪些失败需要确定性工程约束兜底？**

LiDARFoodAgent 已经能作为端云产品工程的素材；ToolAlign 应形成互补：数据管线、MLX 训练、SFT/DPO 数学与实现核验、评测隔离、模型部署、性能归因。这里不承诺任何公司的录取或特定“项目分数”。

最终交付是一个外部开发者能重建实验、检查失败、替换 backend 的研究工程仓库。真实外部用户规模不是十天验收要求；**没有真实用户就不写生产级业务成效**。

## 2. 已确定约束

主要机器为用户提供的 M5 Pro、16 核 GPU、48GB 统一内存 MacBook；不要求多卡，也不默认租 GPU。Mac 原生 MLX 为主，Python/PyTorch CPU 用于小规模参考与损失校验。

一个负责人 kris，加一个 Supervisor 独立对话及独立 worker/reviewer 对话。首期目标十天，假设 kris 每天能实际检查数据、运行结果和关键实现；如可投入时间减少，按阶段门缩范围，不能静默删掉实验协议。

费用基线：不依赖付费模型 API或云 GPU。开源依赖与数据下载可能消耗网络、磁盘和本机电力，仍须记录。任何外部计费另行批准。

## 3. 可检验假设

H1：在固定原始 checkpoint 和评测协议下，SFT 相比未做本项目训练的原始模型，提高工具语义任务成功率。

H2：在同一已验收 SFT 起点上，执行反馈构造的 DPO 样本能改善某些错误类型；可能出现无提升或退化。结论必须按类别和不确定性报告。

H3：有限重试对故障恢复有帮助，但额外 token/延迟的代价可能高于收益。比较固定相同次数/预算。

H4：在同一模型版本和精确相同 prefix 下，cache 能减少重复 prefill；不能把请求变化、暖机差异或质量下降算成优化收益。

容量对照 0.6B vs 1.7B 属于次级问题，不与 DPO 效果混为同一因果比较。量化位宽对照也独立进行。

## 4. 十天必须保住的交付

| 交付 | 需要的证据 |
|---|---|
| 版本化数据 | 来源、许可、revision、切分 manifest、去重与长度报告 |
| 有语义 oracle 的执行环境 | 正确调用成功；运行不报错但任务错误的调用失败；至少一种合理多解 |
| 训练链路 | 原始模型 → SFT；DPO 通过数值和参考模型测试后正式运行 |
| 评测 | 固定测试集、完整分母、分类指标、错误样本、至少一个工程消融 |
| Mac 实测 | 真实硬件、软件版本、token 数、时间、MLX 内存/RSS 独立记录 |
| 可复现与说明 | 干净环境命令、产物 hash、模型卡、局限、独立审查报告 |

目标数据量：先 1k–2k SFT smoke → 通过后 6k–10k 正式 SFT；偏好样本目标 1k–2k **通过 oracle 的有效对**。数量是预算目标，不是越大越合格；保留原始/过滤/最终数量。

本地评测目标 300–500 个**分组隔离**的最终任务实例；不宣称这些实例互相独立。另有 100–200 个 adversarial/故障场景，可与功能测试共用工具但不重复计入总分。BFCL 使用清晰命名的可支持子集，公开完整分类和排除清单。

## 5. 范围分层

**核心交付 A：** baseline、数据治理、SFT、执行评测、资源基线、可复现报告。完成后可发 `v0.1.0-core`，不能声称 DPO 已完成。

**核心交付 B：** 数值核验过的 DPO、与 SFT 同条件比较、负例构造审计。通过后可发 `v0.2.0-preference`。十天目标包含 B，但依赖 P01 兼容性门与实际算力预算；失败时必须明确记为未完成，不更名掩盖。

**核心交付 C：** 本地受限 API、prefix cache 对照、有限重试消融；不可拖垮 A/B。

**后续扩展：** 8/4-bit 与 KV 量化、投机解码、可选 CUDA backend、更多工具域、跨平台导出、LiDARFoodAgent 的只读 shadow 集成。六个月路线见部署文档。

## 7. 不以堆栈数量定义质量

不强制 LangGraph、向量数据库、Redis、Kubernetes 或复杂前端。能用受限状态机清楚表达的流程，不加额外 Agent。服务端仍需 schema、取消、deadline、身份边界和可追溯日志，而不是只有 `/chat` 接口。

关键价值在于：数据为什么可信、测试为什么没泄漏、DPO 学到了什么、失败为什么被正确识别、实际硬件资源如何约束实现。

## 8. 调整规则

所有影响研究结论的调整——数据版本、模型、模板、reference、最大长度、工具集合、指标、测试集、backend——先登记 ADR。只有 Supervisor 合并并分发新契约后，worker 才能改。晚期范围缩减必须保留未完成项和原因。
